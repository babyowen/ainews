## 烟草服务银行失败原因与修复

- 日志 127 的报告状态是 `error`，错误为 `fetch failed`；`pdf_status=skipped` 表示前序失败后没有生成 PDF，并非没有达标新闻。
- 上一个主题 05:11:49 完成，银行于 05:16:49 记录失败，间隔约 300 秒。生产 Node v20.18.1 的内置 HTTP 客户端默认 `headersTimeout` 为 `3e5` 毫秒；自动周报原来采用非流式请求，应用层 480 秒计时并未修改底层响应头等待时间。
- 这些证据高度指向等待响应头超时，但旧代码只保留 `error.message`，丢失 `cause`，不能断言历史底层错误码必为 `UND_ERR_HEADERS_TIMEOUT`。
- 自动任务改为流式接收，在内存中收集完整正文，收到正常结束标记后才入库。对连接/超时、流中断及特定临时 HTTP 错误最多重试一次；无效密钥、无效模型、输出截断不盲目重试。仍使用原模型，每次请求最多 480 秒。
- 保留底层错误码并脱敏，失败日志保留已知入选数、期间总量、输入字符、素材字数及实际耗时。新失败记录的 PDF 状态为 `blocked`；旧 `error + skipped` 组合在界面也显示“报告失败，未生成”。真正无新闻/未达到分数门槛的跳过记录分别说明原因。

## PDF 新闻数量

- 标准版、带联系方式版以及自动周报共用模板，显示 `入选数/期间全部新闻数`，如公积金 `21/123`、银行 `241/931`。
- 分母按相同关键词及 `fetchdate` 起止日期统计，不带评分门槛，包含低分和未评分新闻。自动任务将总量快照保存至新增的可空列 `auto_report_log.total_news_count`；历史记录不伪造总量。
- 手动 PDF 导出由服务端查询分母，不信任客户端传来的总量。原先没有总量的直接渲染调用显示 `—`，不把入选数冒充总量。
- 新闻数量卡片加宽，分母 9pt，数字固定单行；周期与模型卡片继续保持完整显示。

## 新闻与观点的日期规则

`services/weeklyReportEditorial.cjs` 在周报生成及修改时统一应用规则，也适用于生产自定义模板；不覆盖保存的 Prompt 版本、主题范围、地域偏好或两/三栏目结构。实际请求的 debug 信息包含最终规则。

- 有明确期内日期的新闻，在原地域/业务分类内优先排列。
- 缺日期、仅写“近日”、缺采访时间但有事实/出处且没有期外证据的，正常纳入，不加“参考动态”“事件日期未载明”“采访时间未载明”等标签，也不在导语集中解释缺日期。
- 不编造日期，不把采集时间等同于事件日期，不断言日期不明事项本周首次出台或实施。
- 明确期外且没有新增动作的事项剔除；确有必要的背景写明原时间，不能仅靠标出旧日期就把旧事单列为本周重点。明确期外的旧引语从观点摘录删除。实质性事实冲突仍保留必要说明。
- 新闻素材之后追加本次具体起止日期，要求逐事项核对，并合并重复报道中的日期证据；不因一篇文章含有旧背景而误删其中合格的新进展或无过期证据的独立服务事项。
- 原公积金稿的“上海交通大学陈杰（采访时间未载明）”在最终实测新稿中正常呈现为“**上海交通大学陈杰** 表示，缴存记录全国互认便于跨城就业职工在线办理转移。”，与来源新闻 ID 154300 对照，没有靠删除原稿字符串伪造新稿。
