# 周报调试消息一致性

`services/weeklyReportRequest.cjs` 统一组装手动周报请求。`/api/preview-report-message` 与 `/api/generate-report`（含KIMI/SiliconFlow旧别名、流式和非流式）使用同一个函数，因此选定模板、摘要版本、补充要求、模型和已有机关事务来源规则均一致。

原有正式生成的模板回退保持不变：指定模板不存在、读取失败或内容不完整时采用默认模板。调试信息明确显示实际采用的 `promptId`、`promptName`、模型与思考模式；无效ID不会被展示成正在使用的模板。预览不调用模型、不写周报历史。

前端删除了不含服务端规则的本地近似拼装，直接显示服务端返回的真实请求。首次生成和重试都先清空旧调试信息；重试显示保存请求的实际消息，新生成使用当前表单。

不修改提示词文件、机关事务内容规则、模型设置、超时、自动任务或历史报告。测试使用隔离SQL/模型替身及本地浏览器，不触发生产任务。

验证命令：`npm test`、`npm run build`、构建后 `node test/browser-weekly-debug.cjs`。浏览器脚本验证首次生成、表单更改后的重试、重新生成与服务端消息一致。
