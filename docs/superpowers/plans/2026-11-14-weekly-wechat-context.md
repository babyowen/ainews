# 官微来源上下文进入周报 Implementation Plan

> Execute inline with superpowers:executing-plans and test-driven-development; independent review before release.

**Goal:** 仅对「江苏机关事务」下已核验官微，将发布账号、辖区、层级作为独立资料送入手动和自动周报。

**Architecture:** 从 serp_news 已核验注册表生成带来源版本和哈希的38账号只读映射。共享组装函数按微信长链接身份和 sourceapi 匹配，加入每篇独立来源字段；仅在本次模型请求追加地域规则。自动、手动和后端预览共用组装逻辑。

**Tech Stack:** Node.js 20+，CommonJS、Express、node:test；无新增依赖。

**Spec:** 已确认轻量方案；不改标题、正文、已有摘要、数据库结构；仅这个专题官微生效；正文地点优先、转载不套地区。用户特别要求保护固定及生产自定义提示词。

## Constraints and review focus

- 不写任何现有 config 提示词文件或 config/runtime，不改周报门槛、调度、模型、评分和去重。
- 来源辖区不直接等于事件发生地，不把专题名中的江苏强加给外地新闻。
- 按真实链接身份匹配；未知/停用账号、畸形/重复参数、其他专题与其他来源不添加上下文。昵称和自填地区不参与匹配。
- 新规则仅追加到有匹配官微的当次 system 消息，固定与自定义模板原样保留；其他专题请求不变。
- 预览、流式/非流式手动、自动任务、短摘要/全文、潜在客户模板均覆盖。
- 测试隔离数据库、模型、定时任务；冻结真实回填只组装请求，不写周报历史。
- 发布前后逐文件核对所有原 config 文件和共享 runtime/policies/env，禁止覆盖提示词。
