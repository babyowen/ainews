# 周报调试消息与实际请求一致

## 用户确认的发布范围

只发布调试修复。原始默认/自定义提示词、机关事务已有规则、模型选择/思考设置、超时、自动周报和其他专题生成行为保持原样，不修改历史报告。

## 实施与验收

- 将手动模板选择、变量替换、现有编辑规则和模型解析集中至 `buildWeeklyReportRequest`；预览API与三个正式生成入口（含流式）共用，预览不调用模型或写库。
- 保持正式生成已有无效/不完整模板回退行为，debug显示实际采用的模板与模型，不能把请求的无效ID冒充已采用ID。
- 删除前端不完整的本地拼装，显示服务器真实debug；重试继续用保存的请求参数，即使当前表单已改变。
- 对比短/全文、两专题、有效/缺失/未指定模板、三入口和两种传输方式的72组消息；元数据逐字一致，模板文件字节不变。
- 浏览器验证等待服务器前没有错误占位消息；更改表单后重试展示原请求，新生成展示新请求；无生产SQL和付费调用。
- 全套测试、生产构建、一次独立代码复核；发布前后逐文件校验配置哈希和生产就绪状态。

## 复核重点

其他专题生成消息及模型配置是否保持原行为；自定义模板回退和模型标识是否准确；预览确实无调用/写库；浏览器重试是否误读当前表单；修改周报入口是否受意外影响。
