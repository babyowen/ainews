## 1. 目标与推荐范围

来源：https://github.com/babyowen/ainews/issues/25 。Issue 当前开放、无评论。

平台继续服务多个新闻主题；公积金成为优先建设的垂直专区。用户希望把全国公积金的每日新闻、地区与业务浏览、分析报告集中起来，将扬州专用的政策维护和对比放入专区内的子菜单，并为未来调整用户权限保留清晰的结构。

根据本轮用户对“地区和业务政策对比”的描述，首版报告按政策与办理规则比较设计；浏览页展示符合筛选条件的公积金新闻，不用报告的政策证据规则过滤普通浏览。未来若增加综合业务动态报告，再扩展材料规则和 Prompt。

本次范围不包含重新抓取、AI 补标、修改上游标签、自动定时报告、报告历史库或部署。保留现有登录方式、`role + keywords + routes` 用户结构、Express 服务和数据库。地区报告当前没有历史持久化；若需要历史查询，应作为后续需求明确设计。

## 5. 浏览交互与筛选口径

### 浏览方式

公积金专区的三个浏览页面共用新闻视图。每日模式突出单日列表及地区、业务标签；地区模式突出地区树及“地区 AI 报告”入口；业务模式突出两级业务目录及“业务政策 AI 报告”入口。地区和业务页面均保留日期区间和辅助维度筛选，统计规则共用。

- 浏览模式默认最近 30 天；每日模式默认昨天且 startDate=endDate，沿用现有每日新闻的日期习惯。两者都按采集日期筛选，明确说明采集日期不等于政策发布时间或生效时间。
- 地区支持多选；未选择代表全部可见地区，`全国` 只代表全国层级新闻。
- 省份表示“省级＋已识别的下属城市”；“省级”子项只匹配省级标签。
- 没有地区的新闻在“全部地区”和“地区未识别”中可见，不自动归到任何城市。
- 业务类型支持多选一级或二级。不同维度 AND，同维度 OR；一级匹配该一级下任意有效标签。父级和其子级同时选中时消除冗余条件。
- `全部业务`、`无有效标签` 是筛选状态；后者分项展示待标注、未识别、格式异常。
- 每行显示地区及全部业务标签，高亮命中项；分页前执行筛选。
- 切换筛选重置页码；URL 保存日期、地区、业务类型，支持从专区每日新闻跳转、刷新和分享条件。全站每日新闻不增加专有跳转。

### 统计定义

- 总新闻数、每个地区节点和每个业务标签均按新闻 ID 去重。
- 一条新闻可以同时属于两个业务或两个地区，故各项计数之和可能大于总数；页面说明这一点。
- 一级数量是该一级新闻 ID 的并集，不是二级数量相加。
- 地区选项计数应用日期和业务筛选；业务选项计数应用日期和地区筛选。列表总数应用全部条件。
- 已选但变成 0 条的选项仍可见，方便用户取消选择。

## 6. 服务端实现边界

抽取 `services/newsBusinessTypes.cjs`、`services/newsRegions.cjs`、`services/policyNewsQuery.cjs`。将地区常量和精确匹配集中起来，不拆整个 Express 应用。

首版采用有界元数据查询：SQL 先限制关键词、日期、评分，只读取 ID、日期、地区、业务标签等小字段；服务端统一规范化、归并、筛选和计数，最后按当前页或报告命中 ID 读取正文。避免每次加载全部长正文，也避免把 JS 与复杂 JSON SQL 两套规则并行维护。

新筛选入口的初始限制：日期区间至多 366 天、候选元数据至多 10,000 条、每页至多 100 条。超过限制明确提示缩小区间，不静默截断。上限应在性能验证后评审；它们不是已测得的容量。

接口：

- 扩展 `GET /api/policy/regions`：支持业务条件，保留原有树结构并增加统计元数据。
- 增加 `GET /api/provident-fund/news`：公积金每日入口的薄路由，固定关键词并验证该页面权限，复用统一查询服务；不依赖前端传 keyword 来限定数据。
- 扩展 `GET /api/policy/region-news`：支持重复 `regions=city::南京` 参数和 `businessTypes` JSON；兼容旧单地区参数。返回 rows、total、page、pageSize、totalPages。
- 增加 `GET /api/policy/business-types`：按当前日期和地区返回一级/二级选项与数量。
- 增加 `GET /api/provident-fund/business-news`：业务新闻薄路由，验证业务浏览页权限，复用统一查询与统计服务。
- 保留地区报告的 `/api/policy/region-report/news|generate|export-pdf`：服务端固定为地区报告，使用原地区报告页权限，并返回实际材料快照。
- 增加业务报告的 `/api/provident-fund/business-report/news|generate|export-pdf`：news 使用 GET，generate/export-pdf 使用 POST；薄路由复用报告服务，固定为业务政策报告并校验该页面权限。预览返回 previewHash；生成接受单业务、地区、previewHash、Prompt ID 和人工选择。
- 报告类型由服务端路由指定，不信任客户端 mode；地区报告入口不能通过参数调用需要另一项授权的业务报告。

所有参数先规范化和校验；未知一级、非法地区层级、无效日期、过大页码/页大小返回明确 400。排序字段使用白名单，SQL 值使用参数绑定。元数据和正文读取使用同一只读事务，确保一次响应内部一致。

涉及每日入口、地区浏览、预览、生成、导出及扬州专用流程的接口，按第 1B 节验证用户登录、公积金关键词权限及对应页面权限。共用 facets 可供任一对应公积金浏览/报告权限读取，但生成和政策写入仍验证各自叶子权限。前端补传现有 `authHeaders()`，相关调用方一并更新。

数据库缺字段时返回“业务类型数据暂不可用”，不得通过网页请求执行 ALTER 或补标。无别名表时明确声明仅能读取原始有效标签；权限错误、连接错误不伪装成无别名。

## 7. AI 报告设计

### 专题范围

地区 AI 报告保留原有单地区演变与多地区综合比较；业务政策 AI 报告使用独立页面入口，选择一个一级业务（宽口径）或一个精确二级业务（推荐），再选择 2—10 个地区。内部复用同一报告组件，以固定 reportKind='region' 或 'business' 配置，不提供跨类型模式开关。业务报告不能选择多个不相关业务，不能用未分类材料自动推断分类。

示例：`贷款 → 贷款额度调整`，选择扬州、南京、苏州，核对材料后生成横向比较。

预览按地区显示命中数、默认纳入数及排除理由。专题模式不沿用“一律排除指南”的规则：

- 明确政策调整可作为变动证据。
- 办事指南、问答、解读可作为办理口径或既有规则证据，必须明确材料性质。
- 企业财务公积金等明显不相关内容默认排除。
- 用户可人工纳入或排除，但只能操作当前专题查询的候选 ID。
- 少于两个地区有可用材料时不生成跨地区比较，显示不足地区及原因。

### 证据和一致性

- 每条材料包括稳定的 `[N新闻ID]`、标题、原文链接、来源、采集日期、地区、业务标签、摘要及必要正文。
- 同一新闻全局只提供一份；各地区段落引用其 ID。多地区新闻不得机械展开成逐地区确定政策。
- 报告范围由服务端输入确定；用户补充说明和抓取文本不能扩大来源范围。
- 预览 hash 覆盖服务端固定的报告类型、标准化筛选、归并结果、候选 ID、材料字段和默认纳入判定。生成前重新读取并核对，不一致返回 409，要求重新预览；不同报告类型不能复用预览。
- 模型调用使用核对后的同一份内存材料；人工选择先校验为候选集子集。最终返回实际输入的来源清单、hash、Prompt ID、Prompt 内容 hash、模型 ID、业务条件、各地区样本量。
- 输入上限暂定候选 200 条、最终 Prompt 180,000 字符。超限要求缩小范围，不自动删除新闻或截断摘要；上线前通过样本验证这一限制。
- 快速切换筛选时丢弃旧请求响应；条件、Prompt 或人工选择变化后旧报告失效，禁止用新条件包装旧 PDF。

### Prompt 与输出

在现有 `region-policy-report-prompts.json` 追加 `business-topic-comparison-v1`，不设为全局默认。使用现有配置存储结构和 CRUD；专题模式默认推荐此 ID。显式请求不存在的 Prompt ID 必须报错，不能静默回退。

通过服务端统一上下文提供专题、样本覆盖和事实约束，即便管理员使用已有自定义 Prompt，也不能遗漏选中业务范围。Prompt 管理仍写运行时层。

报告包含：

1. 样本范围与覆盖情况。
2. 同一业务的地区对比表：对象、条件、额度/比例、期限、办理方式、原文明确的生效时间。
3. 共性与差异。
4. 分地区观察及有依据的可借鉴做法。
5. 缺失信息、冲突材料与来源清单。

关键数字和政策事实标注 `[N新闻ID]`。没有证据写“材料未提及”，没有新闻写“本次样本未覆盖”；不得写成“该地区没有此政策”。新闻报道不自动等同于完整、现行有效的政策清单。对于同一地区冲突信息，呈现来源和时间，不自行合并为新事实。

输出结构和来源 ID 做确定性检查；具体事实是否被来源支持，还必须人工抽样验收。技术检查通过不能证明报告内容正确。

### PDF

复用现有渲染器。标题包含业务专题，元信息包含日期、地区、样本数、Prompt 和模型，参考新闻保留 ID 与安全的 http/https 原文链接。导出使用生成时服务端返回的快照，不重新读取当前预览。

## 8. 分阶段交付与验收

1. **专区结构与轻量权限整理**：菜单定义、地区/业务/扬州分组、既有页面搬迁、用户管理分组、权限撤销和入口刷新。新增入口与对应页面一同完成后再发布，不提供尚未注册的菜单链接。
2. **公积金浏览能力**：统一查询和统计，分别完成专区每日新闻、地区新闻、业务新闻三个入口。全站每日新闻继续包含公积金但不显示专有字段；原四个页面路径保持有效。
3. **两类报告与 PDF**：地区 AI 报告放在地区分组，业务政策 AI 报告放在业务分组，完成条件交接、证据预览、专题 Prompt、输入一致性、来源引用和导出；扬州专用对比逻辑维持原职责。

每阶段提交可独立审查的改动，推荐“专区结构＋浏览”和“专题报告”分成两个 PR。默认在本会话逐项实施。合并、生产发布和真实付费模型验收另行确定。

验收至少覆盖：

- 专区位于全站每日新闻之后，旧政策父菜单消失；全国通用功能与扬州专用功能归属正确。
- 地区与业务是独立浏览入口，各自包含对应的 AI 报告入口；同一筛选条件返回一致新闻，报告类型不能通过参数切换来绕过授权。
- 全站每日新闻仍能查询公积金，单选公积金或混合新闻时都不展示地区、业务类型和标注状态；专区页面正常展示这些字段。
- 所有旧 URL 可访问，深层页面自动展开两个父级；移动端三层菜单不截断且可键盘操作。
- 只有获准叶子才可见，无子项父级隐藏；全国通用授权不自动授予扬州功能。
- 撤销内置用户页面权限后再次读取/登录不会补回；无可用首页不发生循环跳转。
- 公积金每日入口无法通过 query/body 切换为其他关键词，与区间浏览共用筛选口径。
- 双标签、同一级双标签、多地区和省市重叠不会重复增加总数。
- `NULL / [] / 其它 / 格式异常` 的含义不混淆；别名链和循环有测试。
- 浏览、预览和模型输入都只包含选中业务；全国层级不冒充全部地区。
- 省级仍要求 score ≥3；城市别名和精确匹配保持一致。
- 材料更新后生成返回 409；越权、越界 ID、未知 Prompt、空样本不调用模型。
- 快速切换业务不会展示旧结果；URL 恢复、移动布局、分页和 PDF 均验证。
- 固定一组真实样本人工核对关键结论、数字、地区归属及来源，单独记录报告质量结果。

实施步骤见同日的 implementation plan。
