## 权限及已有用户

继续使用 `role + keywords + routes`。管理员按 role 拥有完整访问；受限用户需同时具备“公积金”关键词和具体叶子路由。浏览、报告、扬州功能分别授权，父分组不授予权限。

`config/runtime/users.json` 存在时，权限以它为准。读取和登录不再自动补回内置账号的旧路由。旧用户不会自动获得三个新增入口：管理员在用户管理页勾选后保存即可。页面启动通过 `/api/auth/me` 刷新资料；401 清理会话，公积金请求遇到403时刷新权限。管理自己的权限后也刷新。空权限用户显示说明，不发生循环跳转。

## 数据口径

- 固定关键词为“公积金”，评分至少3；参数不能改写这两个条件。
- 日期为 `fetchdate` 采集日期，不等于发布或生效日期。保留 mysql2 DATE 的本地日历日期，避免 UTC 转换导致少一天。
- 一级业务为缴存、提取、贷款、其它；身份为 `(level1, level2)`。别名按 `news_table=scored_news` 读取，可沿链归并；循环、错误 JSON 和结构异常标为异常，不写回数据库。
- NULL 为待标注，空数组为未识别，均不视为“其它业务”。页面显示标注覆盖统计。
- 已知地区别名归一化，“全国”与全部地区分开；省名仅作为展开入口，内含“全省”“省本级”和城市。“全省”包括省级和下属城市，“省本级”只指省级本身。吉林市保持城市身份。无法识别的地区进入未识别计数，原始文本仍保留。
- 同维度 OR，不同维度 AND；新闻按 ID 去重后排序、分页。父分类数量和平均分按新闻 ID 集合计算。新闻可属于多个分类，因此分类数量相加可能超过总数。
- 地区 facet 忽略地区选择，业务 facet 忽略业务选择，各自保留另一维度条件。已选零计数项仍可取消。
- 查询使用独立、可重复读的只读事务：候选元数据 → 精确筛选 → 分页 → 本页正文。连接在 finally 释放。

边界：区间1–366天；元数据最多10,000条；每页1–100条；报告候选最多200条；最终 Prompt 最多180,000字符。超限明确报错，不静默截断。别名表缺失时显示降级提示；其他 SQL 错误不伪装成空结果。网页请求不建表、不建索引、不补标。

## 报告与 PDF

报告页面按四步组织：选择时间、选择地区（业务报告为“选择业务类型”）、核对材料、选择模板并生成。预览材料以表格列出纳入状态、新闻与来源、地区、业务及筛选原因，支持勾选调整和展开正文。条件变化后需重新预览。

地区报告支持1–10个地区，可生成时间线或通用比较；业务报告仅要求选择一个一级或精确二级业务，日期默认截至昨天的前7个完整自然日，预览和生成均不要求选择地区；即使 URL 或旧请求带有地区条件，也会清除后按业务读取各地材料。一个地区或地区不明也可生成，地区覆盖从实际材料计算，PDF 同步使用实际纳入材料覆盖。两种用途由各自接口固定，客户端不能通过 `reportKind` 切换权限。

预览展示候选、自动纳入理由、材料类别及地区覆盖，允许人工纳入/排除。业务报告保留有材料的指南/问答作为既有规则；依据明确的资本公积、盈余公积、转增股本信号排除企业财务公积金，不能因“股东”等泛词剔除住房公积金欠缴案例。纯会议、调研、宣传、临时服务安排、预测及无正文和摘要的材料默认排除；含具体业务规则的活动、涉及还款及征信权益的暂停通知保留。草案与欠缴/执法案例单独标明性质。规则为可核对的启发式筛选，并非模型语义核验；除财务公积金外，用户可手动调整。多地区、多标签属于新闻级属性，不能据此推断每项政策适用于所有组合。

生成前在只读事务中重新取得材料并核对 `previewHash`。正文、摘要、标签、别名、筛选或类型改变时返回409，要求重新预览。外部 ID 和非布尔人工调整被拒绝。生成消息中每篇新闻只出现一次，保留标签、原始地区、来源及链接。业务报告仅使用数据库摘要（最多500个 Unicode 字符，含标点），缺失时使用正文开头摘录并标记来源与截短状态，不将全文发送给模型；地区报告仍使用原文与摘要。自动筛选、人工核对及预览 hash 仍基于完整材料。业务提示词明确摘要未覆盖的细节需核对原文，不能据此推断不存在。快照包含实际纳入来源、覆盖、Prompt 内容 hash 和模型名。

业务报告默认采用业务政策简报 V3，先呈现核心判断，再展开重点政策与影响、值得借鉴的做法。篇幅通常800至1500字，材料少时缩短或合并章节；不写样本覆盖和功能机制。地区表可选，最多一张、3至5个代表性事项、最多4列；缺项和冲突仅在影响结论时就近说明，不单列检查清单。关键事实使用 `[N新闻ID]`。服务端检查空输出和引用 ID，不再强制五个固定章节。合并引用、全角括号和数字会规范化为独立的 `[N数字编号]`，每个编号仍需属于实际纳入材料；不按顺序号推测映射，不扩展编号范围。提示词列明允许引用清单。真实错号、格式错误或缺少引用时，允许模型对照原证据校正一次（仍遵守180000字符边界），再次校验；失败返回具体无效编号且不签发 PDF 快照，成功后的签名基于规范化正文。该检查无法证明事实语义正确；真实模型质量仍需另行验收。前端引用可定位到来源列表。

本地模型调用需要当前供应商配置指定的环境变量；Agent Router 使用 `AGENT_ROUTER_API_KEY`。缺失时在网络请求前返回503及 `MODEL_API_KEY_MISSING`，页面提示管理员补齐配置。其他未分类生成失败记录脱敏错误，页面不再将其归因为输入过长。

PDF 使用生成响应中的签名快照，不重新组装当前预览。服务端核对签名和报告类型；修改过的正文或快照无法导出。报告条件、模板、补充要求或人工选择改变后旧报告失效。PDF 展示专题、日期、地区、模型、Prompt 和来源 ID；仅 http/https 原文链接可点击。旧 PDF 模板调用不传业务字段仍可渲染。

财务内容识别的边界：标题或摘要命中“资本公积、盈余公积、转增股本”时直接排除；仅正文命中时，只有整篇材料缺少明确住房公积金语境才排除，避免“比例10%”“额度100万元”等企业财务规则进入业务报告。住房公积金、管理中心、公积金贷款或缴存/欠缴/补缴等语境会保留后续分类机会，不因正文中的对比性财务提及直接排除。混合或含糊材料仍需人工核对，不能把该规则视为完整语义识别；确认为 `financial-reserve` 的材料禁止人工强制纳入。本次补强仅适用于业务报告，地区报告分类保持原有规则。

引用校正的长度上限包括原始输入、模型草稿和校正要求。总长度超过180000字符时不会发起第二次模型调用，接口返回502及 `REPORT_VALIDATION_FAILED`，保留引用错误并说明“未执行自动校正：校正输入超过180000字符上限”，提示减少材料或缩短补充要求后重试。此时 `citationRepairAttempted=false`，不签发导出快照。

## Prompt 配置

复用 `region-policy-report-prompts.json` 和原 CRUD。业务页面和后端默认使用 `business-topic-brief-v3`（业务政策简报 V3），保留旧 `business-topic-analysis-v2` 和 `business-topic-comparison-v1`，不改变地区全局默认。业务报告不允许选内置地区模板，以免“只分析新政”的地区要求与业务指南分析冲突。V2 明确500字摘要证据边界、单/多/未知地区的处理、选定业务边界、草案与个案性质、采集与生效日期、重复报道、摘要证据局限及引用要求。地区/业务页面各自固定用途，管理员可编辑、另存、删除、恢复版本。显式选择不存在的 ID 会报错；删除默认专题产生的运行时墓碑不会被出厂回退绕过。服务端业务上下文、材料归属和引用约束始终保留，不依赖模板是否包含占位符。

业务自定义 Prompt 用于调整简报的关注点和表达要求，不能完全替换服务端写作要求。除 ID 为 `business-topic-comparison-v1`、`business-topic-analysis-v2` 的两个旧版本外，所有业务模板（含自定义 ID）都会追加简报顺序、通常800至1500字、最多一张表等写作要求，以及事实、摘要和引用约束。将 V1/V2 内容另存为新 ID 也会采用这一简报要求；编辑原 ID 则保留旧版结构要求。请避免在自定义模板中写入相冲突的篇幅或结构。章节顺序属于模型写作要求，不是服务端逐章验收条件；地区报告不注入业务简报结构。
