# Agent Router 模型统一迁移

## 变更

所有模型生成入口统一为 Agent Router 的 `DeepSeek-V4.1-Flash`。手动周报、自动周报、周报修改、政策提取/比对、地区政策报告共用配置和客户端，前端移除模型选择。Google Custom Search 属于搜索 API，不在模型迁移范围内。

政策提取旧流程存在：V4 Pro 的 4096 token 全被思考耗尽，空正文被替换为 `{}`，再进入比对并显示“对比生成失败”。现在关闭思考并使用 32768 token 预算，明确拒绝截断、空正文、空政策结果；报错显示具体原因。JSON 格式错误最多修复一次。

流式解析支持跨网络分块的 SSE 与 UTF-8，收到完整结束后才保存报告；中途断流或截断返回错误。供应商模型列表检查失败、密钥缺失或 API 失败时，不回退到旧供应商。

## 配置与部署

1. 备份服务器当前发布版本，以及 `.env`、关键词/地区/政策提示词、`config/auto-report-config.json`、`config/users.json` 和 `config/policies/`。保留现有数据库及 PDF 文件。
2. 在服务器 `.env` 中新增 `AGENT_ROUTER_API_KEY`，填写相同供应商的有效密钥。不要把本地 `.env` 整体覆盖到服务器，不要输出密钥到日志。
3. 部署代码与构建产物，核对 `config/weekly-report-models.json` 的模型 ID 为 `DeepSeek-V4.1-Flash`。其余生产调优配置保留原值；旧自动任务模型 key 会在运行时统一解析，无需覆盖整份自动任务配置。
4. 重启 Node/PM2 进程，让新环境变量生效。确认代理的读取超时足够覆盖单次最长 180 秒模型请求。
5. 检查 `/api/weekly-report/models`、`/api/policy/models`、`/api/llm/models` 只返回新模型，页面没有模型选择下拉框。
6. 用一份小周报验证政策提取/比对、流式周报和修改。只有实际启用生产自动任务时，才验证自动周报保存/PDF/下载；不要用验收动作触发全部生产关键词。

供应商当前文档公布的地址为 `http://api.agent-router.cn/v1`，该地址不提供传输加密。若供应商提供 HTTPS 地址，应先验证模型列表与生成接口再调整 endpoint；不要自行猜测 HTTPS 地址。参考：[Agent Router 文档](https://www.agent-router.cn/docs)

回滚时恢复备份发布版本和匹配的配置文件、环境变量，再重启服务；此次迁移不涉及数据库 schema 变更。不要用回滚覆盖已经生成的历史报告和 PDF。
